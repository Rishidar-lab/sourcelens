# Week 2 demo script — SourceLens

Target length: 3–5 minutes. Spoken cues in **bold**, on-screen actions in
*italics*. Prepared as an exact recording sequence — no recording exists yet
at the time this script was written; follow it live rather than treating it
as a description of a finished recording.

---

**1. Introduction (20s)**

*Show the running app, header visible.*

> "This is SourceLens — an evidence-grounded document assistant I built for
> Week 2. The core idea: it should never answer from what the model already
> knows. It should only answer from documents you actually give it, with
> citations, and it should refuse cleanly when those documents don't cover
> the question."

**2. Upload synthetic documents (30s)**

*Drag the 7 files from `qa/corpus/` onto the Knowledge Base panel — or the
smaller `samples/` set for a quicker upload.*

> "I'm uploading a small synthetic corpus — HR policies, an incident
> response policy, a security guidelines doc, and one document that's
> deliberately adversarial, which I'll come back to. Each one gets parsed,
> chunked, embedded with a real sentence-transformer model, and stored in a
> local vector database."

*Point at chunk counts appearing next to each "Indexed" badge.*

**3. Indexing (10s)**

> "Embeddings are computed once per document and reused — the model itself
> loads once at startup, not per request."

**4. Direct grounded question (30s)**

*Type: "How many days per week may an eligible employee work remotely
under the current policy?" Click Ask.*

> "A direct factual question. SourceLens retrieves the relevant chunk,
> passes it to the LLM with an explicit instruction to answer only from
> that evidence, and returns a grounded answer."

**5. Citation expansion (20s)**

*Click the source card to expand the excerpt.*

> "Every citation traces back to a real retrieval record — filename, page
> or section, the actual excerpt, and a relevance score. None of this is
> generated by the model; it's built from what was actually retrieved."

**6. Multi-document question (30s)**

*Type: "Which teams should I contact for a secure-access problem versus a
suspected incident?" Click Ask.*

> "This one needs evidence from more than one document — security
> guidelines and incident response policy both contribute, and both show
> up as separate citations."

**7. Unsupported question — the core acceptance test (30s)**

*Type: "Who won the 2018 FIFA World Cup?" Click Ask.*

> "This is the important one. Vector search will still return its closest
> matches from the policy documents — 'closest' isn't the same as
> 'relevant.' SourceLens has an evidence-sufficiency gate that catches
> exactly this case and refuses instead of guessing. No hallucinated
> answer, no silent fallback to the model's own knowledge."

**8. Current-vs-legacy conflict (30s)**

*Type: "One file says two days and another says three. Which statement
should a reviewer quote, and why?" Click Ask.*

> "The corpus includes a superseded 'legacy' remote-work policy alongside
> the current one, on purpose. SourceLens is instructed to surface a
> conflict explicitly rather than silently pick a source — and here it
> should identify the current policy using the supersession note, not just
> whichever chunk ranked first."

**9. Architecture, in one breath (30s)**

> "Backend is FastAPI with a persistent ChromaDB vector store and a real
> sentence-transformer embedding model. LLM backend is pluggable — Gemini,
> any OpenAI-compatible endpoint, or a local Ollama server, which is what's
> running right now. Frontend is React and TypeScript. Everything here —
> the retrieval numbers, the citations, the refusal — is live, not staged."

**10. GitHub repository (10s)**

*Show the repo, README open.*

> "Full source, the 35-test backend suite, the QA benchmark it was measured
> against, and the write-up of exactly what I found and fixed while getting
> this running, are all in the repo — link below."

## Recording notes

- On shared/CPU hardware a real LLM answer can take anywhere from ~30
  seconds to a few minutes (see `docs/EVALUATION.md`) — either record on
  hardware with a faster local model / a hosted API key configured, or cut
  the wait in editing and say so.
- Beat 8 depends on the LLM correctly reasoning about the supersession
  note; if the live answer doesn't quite nail it, that's an honest result —
  don't re-record until it says what the script above claims. Report what
  actually happened.
